# PUBG MegaFon IPv6/NAT64 Relay

Локальное исправление зависания PUBG PC на сером экране загрузки при подключении через мобильный интернет MegaFon. Работает без VPN, VPS и перенаправления всего трафика компьютера.

**English:** A local Windows IPv6/NAT64 relay for PUBG PC when MegaFon mobile internet causes an infinite grey-smoke loading screen, broken lobby UI or failed matchmaking. No VPN or VPS required.

## Симптомы

- PUBG запускается и проходит авторизацию, но зависает на экране с серым дымом;
- через другого оператора игра работает;
- через MegaFon с VPN игра работает;
- проблема одинаковая при Wi-Fi hotspot и USB-модеме;
- иногда лобби открывается частично, но не работает интерфейс, кастомизация или поиск матча;
- после одного боя может перестать работать WebSocket лобби.

Проверено на Windows 11 и PUBG PC из Steam при раздаче интернета со смартфона MegaFon.

## Кратко о причине

В захватах трафика соединение с AWS Global Accelerator PUBG на TCP `40002` успешно проходило трёхстороннее рукопожатие:

```text
SYN -> SYN-ACK -> ACK
```

После передачи первых прикладных данных нормальный ответ не приходил, начинались повторные передачи. Это указывает на проблему конкретного пути:

```text
MegaFon IPv4/CGNAT -> AWS Global Accelerator -> PUBG TCP 40002
```

Точное место сбоя внутри сети оператора или AWS не доказано. Возможные причины: stateful CGNAT/firewall, фильтрация трафика либо несовместимость маршрута MegaFon с данным сервисом AWS. Это не доказательство намеренной блокировки PUBG.

## Что делает исправление

Скрипт разделяет трафик PUBG по назначению:

| Трафик | Маршрут |
|---|---|
| HTTPS с настоящим AAAA | Напрямую через IPv6 MegaFon |
| IPv4-only HTTPS | Через NAT64 MegaFon `64:ff9b::/96` |
| Служебный TCP `40002` | Через автоматически выбранный публичный NAT64 |
| Игровой UDP | Напрямую через MegaFon, без relay |

Для TCP `40002` проверяются доступные NAT64-префиксы. Выбор выполняется сначала по минимальному числу неудачных TCP-проб, затем по медианной задержке.

Также реализация:

- сохраняет настоящий SNI каждого PUBG-домена;
- назначает каждому HTTPS-домену отдельный `127.0.0.x`, чтобы Chromium/CEF не объединял разные сервисы в одно HTTP/2-соединение;
- отключает прикладной тайм-аут после TLS ClientHello;
- включает TCP keepalive через 30 секунд для WebSocket BIFROST;
- автоматически восстанавливает `hosts` и удаляет временные loopback-адреса после закрытия.

## Установка и запуск

1. Скачайте архив из раздела **Releases** и распакуйте его.
2. Полностью закройте PUBG.
3. Запустите `START_PUBG_IPv6_RELAY.cmd`.
4. Подтвердите запуск от администратора.
5. Дождитесь строки:

   ```text
   PUBG Russian-first hybrid relay v12 is RUNNING.
   ```

6. Запустите PUBG и не закрывайте окно relay во время игры.
7. После выхода из PUBG закройте окно relay — очистка выполнится автоматически.

Если окно было завершено аварийно, запустите `STOP_AND_RESTORE.cmd` от администратора.

## Диагностика

Во время работы relay запустите:

```text
TEST_PUBG_IPv6_RELAY.cmd
```

Отчёт сохраняется в папку `PUBG-MegaFon-Diagnostics` на рабочем столе текущего пользователя. Файл `PUBG-IPv6-Relay-target.txt` рядом со скриптом показывает выбранные маршруты, медиану задержки и потери TCP-проб.

Перед публикацией отчёта проверьте его содержимое: таблица маршрутизации и DNS-ответы могут содержать ваши локальные или публичные IP-адреса.

## Что исследовалось и не помогло

- проверка файлов PUBG и Steam;
- другой сетевой адаптер и драйверы;
- смена DNS;
- ручная подмена CloudFront IP в `hosts`;
- Wi-Fi hotspot вместо USB-модема и наоборот;
- смена APN и принудительный IPv4;
- обычные профили Zapret для TCP `80/443`;
- Fake TLS и стандартные DPI-desync-профили;
- отдельный Zapret-профиль для TCP `40002`;
- `multisplit` первого прикладного сообщения на TCP `40002`;
- перенаправление всех PUBG-сервисов через один зарубежный NAT64.

Последний вариант открывал лобби, но давал высокий пинг, нестабильный интерфейс и разрыв WebSocket после матча. Рабочим оказался гибридный маршрут: российский MegaFon IPv6/NAT64 для основной части сервисов и внешний NAT64 только для сломанного TCP `40002`.

## Подтверждённый результат

В тестовой конфигурации:

- PUBG стабильно открывает лобби;
- работают меню, кастомизация и матчмейкинг;
- можно сыграть несколько матчей и вернуться в лобби;
- пинг в матче — примерно `35–45 мс`;
- при выборе маршрута TCP `40002` — `0%` потерь тестовых TCP-подключений.

Результат зависит от региона, базовой станции, текущих маршрутов MegaFon и доступности сторонних NAT64. Скрипт не может исправить потери игрового UDP внутри сети оператора.

## Безопасность и приватность

- Скрипт имеет открытый исходный код и не отправляет телеметрию.
- Требует администратора только для изменения `hosts` и временных loopback-адресов.
- Не перехватывает TLS: данные пересылаются без расшифровки.
- Не содержит VPN-клиента, SOCKS-прокси, учётных данных или удалённого управления.
- Не публикуйте необработанные ETL/PCAP и диагностические файлы без проверки на IP-адреса и системные данные.

## Ограничения

- Это экспериментальное community-решение, не связанное с KRAFTON, PUBG Studios, AWS или MegaFon.
- Публичного российского NAT64, подходящего для TCP `40002`, на момент разработки не найдено. Произвольный российский IPv6 использовать нельзя: за префиксом должен реально работать маршрутизируемый NAT64-шлюз.
- После изменения инфраструктуры PUBG или MegaFon список доменов и логика выбора маршрута могут потребовать обновления.
