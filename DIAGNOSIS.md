# Диагностика проблемы

## Наблюдаемая последовательность

1. DNS возвращает адреса AWS Global Accelerator PUBG.
2. Клиент устанавливает TCP-соединение с портом `40002`.
3. Первые прикладные данные уходят от клиента.
4. Полноценный ответ отсутствует, появляются retransmission.
5. PUBG остаётся на сером экране либо загружает неполное лобби.

Через другого оператора и через VPN та же установка PUBG работает. Следовательно, файлы игры, Steam, Windows и оборудование не объясняют симптом.

## Что доказано захватом

```text
TCP handshake: PASS
Client application data: SENT
Normal server application response: NOT OBSERVED
Retransmissions: OBSERVED
```

Профиль Zapret действительно изменял разбиение первого сообщения на TCP `40002`, но результат не изменялся. Поэтому простая DPI-десинхронизация или TCP segmentation не устраняет сбой.

## Что не доказано

Нельзя утверждать, что MegaFon намеренно блокирует PUBG. Захват на клиенте не позволяет разделить:

- ошибку CGNAT/stateful firewall MegaFon;
- потерю на межоператорском маршруте;
- политику AWS/PUBG по отношению к конкретному пулу CGNAT;
- более глубокую обработку игрового протокола.

Практический вывод уже достаточен: прямой IPv4-путь MegaFon для служебного TCP `40002` непригоден, а IPv6 и альтернативный NAT64 работают.

## Почему гибрид лучше полного NAT64

Полный relay всех PUBG-сервисов через один зарубежный NAT64 создавал лишний обходной маршрут для HTTPS, изображений и WebSocket. Это повышало задержку и делало лобби нестабильным.

Гибридная схема оставляет большую часть трафика в сети MegaFon и выносит наружу только проблемное соединение `40002`.
